# EJ Learning — системийн шаардлага

> Төлөв: **ноорог v0.1** · Огноо: 2026-09-17
> Эх сурвалж: захиалагчийн амаар тайлбарласан шаардлага + `ej_learning_dev` DB-ийн бодит бүтэц.
> Уншаад засварлах хэсгээ тэмдэглэнэ үү. Тодорхойгүй зүйлсийг §11-д цуглуулсан.

---

## 1. Зорилго

Сурагчийн **бодит түвшинг оношилж**, дутуу эзэмшсэн чадвар бүрт нь тохирсон
материалыг өдөр тутам хүргэдэг систем. Гол ялгаа нь: сурагч бүх зүйлийг
дараалан үзэхгүй — оношилгоо нь ямар чадвар дутуу байгааг олж, түүнийг
нөхөх зам (шаардлагатай бол доод ангийн агуулга руу буцаж) автоматаар
зурагдана.

---

## 2. Хэрэглэгчид ба эрх

| Дүр | Тайлбар |
|---|---|
| **Сурагч** (`STUDENT`) | Өдрийн хичээл үзнэ, quiz бөглөнө, өөрийн ахицаа харна |
| **Бага ангийн багш** (`TEACHER`, бага) | 1–5-р анги. Оношилгоог **цаасаар** авч, үнэлгээг системд гараар оруулна |
| **Дунд/ахлах ангийн багш** (`TEACHER`, дунд-ахлах) | 6–11-р анги. Оношилгоо системд өөрөө явагдана; багш үр дүнг хянана |
| **Админ** (`ADMIN`) | Ном, сэдэв, чадвар, хуваарийн default тохиргоо; хэрэглэгчийн удирдлага |

**Онцлох**: багшийн 2 төрөл нь зөвхөн дэлгэц өөр биш — **ажлын урсгал нь өөр**.
Бага ангийн багш үнэлгээ *оруулдаг*, дунд/ахлах ангийн багш үнэлгээг *хянадаг*.

> Одоогийн `core.user_role` enum: `STUDENT, TEACHER, ADMIN`. Багшийн шатлалыг
> тусад нь хадгална (§9.1), enum-д `TEACHER_PRIMARY` нэмэхгүй — учир нь нэг багш
> хоёр шатанд хичээл заах боломжтой байх ёстой.

## 4. Оношилгоо

### 4.1. Дунд/ахлах анги (6–11) — вэб дээр

- Олон сэдэв хамарсан, **олон асуулттай**, **хугацаатай**
- Эхний ээлжинд бүх асуулт **сонголттой (тест)**
- Хугацаа дуусахад автоматаар илгээгдэнэ
- Систем оноог тооцоод чадвар бүрээр түвшин гаргана

### 4.2. Бага анги (1–5) — цаасаар

- Сурагч **дэвтэр дээрээ** гүйцэтгэнэ
- Багш шалгаад **системд оноо/түвшин оруулна**
- Багш өөрөө түвшинг тодорхойлж болно (системийн тооцооллыг дарж)
- Оруулсан багш, огноо бүртгэгдэнэ (`audit.change_logs`)

### 4.3. Хоёуланд нийтлэг

- Үр дүн нь `learning.student_skill_mastery`-д чадвар тус бүрээр буудаг
- Оношилгооны түүх хадгалагдана (сар бүрийн ахицыг харах)

## 5. Ном ба өдрийн хуваарилалт

### 5.1. Ном

- Эхний ээлжинд **PDF**, **зөвхөн 1 ном**
- Ном → бүлэг → дэд бүлэг бүтэцтэй, хуудасны мужтай
- Номын хэсэг ↔ сэдэв холбогдоно

### 5.2. Хуваарь

- Ном 3 улирлын хугацаанд сэдэв/дэд сэдвээр хуваагдана, **анги бүр дээр**
- Аль өдөр ямар агуулга өгөхийг:
  - **Багш сонгоно**, эсвэл
  - **Админы default хуваарийг** ашиглана
- Сурагчид өдөр бүр номын тодорхой хэсэг оноогдоно

## 6. Чадвар ↔ сэдэв холбоо (миний санал)

Та асуусан: *"сэдэв олон ч skill нь дотроо хэд хэдэн сэдэв агуулж болно.
Нэг skill нь л муу гээд тэр сэдвүүдийг дахин давтах уу?"*

### Санал: **сэдвээр биш, чадвараар нөхөх**

**Яагаад:**

1. Сэдэв бол *хүргэх сав*, чадвар бол *эзэмшлийн нэгж*. Нэг сэдэв 5 чадвар
   заадаг бол, 1 чадвар дутуугаас болж бүх сэдвийг давтуулах нь сурагчийг
   аль хэдийн эзэмшсэн 4 чадвар дээр дахин суулгана — **цаг дэмий, урам хугарна**.

2. Танай DB аль хэдийн ингэж загварчлагдсан:
   ```
   content.content_skill_maps   сэдэв ↔ чадвар (олон-олон, is_primary тэмдэгтэй)
   content.skill_dependencies   чадвар → урьдач нөхцөл чадвар
                                (REQUIRED/RECOMMENDED/RELATED × HIGH/MEDIUM/LOW)
   ```

3. Ангиас ангид ухрах гинж **бэлэн бий**:
   ```
   MGL09-TEXT-STRUCT  ←REQUIRED/HIGH←  MGL08-TEXT-STRUCT
   MGL09-MAIN-IDEA    ←REQUIRED/HIGH←  MGL08-MAIN-IDEA
   ```
   Энэ бол яг таны хэлсэн "8-р ангийн хичээлийг эхэлж ойлго" гэсэн урсгал.

4. `learning.daily_lessons.lesson_type` нь `CORE / RECOVERY / REINFORCE` гэсэн
   3 төрөлтэй — нөхөх хичээл нь тусдаа төрлөөр аль хэдийн тодорхойлогдсон.

### Алгоритм

```
1. Оношилгооноос GAP чадваруудыг ав
2. GAP чадвар бүрт:
     skill_dependencies-ээр REQUIRED + HIGH урьдач нөхцөлийг ол
     хэрэв тэр урьдач нөхцөл ч GAP бол → гүнзгий рүү үргэлжлүүл (рекурс)
3. Хамгийн гүнд байгаа эзэмшээгүй чадвараас эхэл
4. Тухайн чадварыг заадаг агуулгыг ол:
     content_skill_maps (is_primary = true)
5. Агуулгын номын хуудсыг ол:
     content_source_alignments → page_from, page_to
6. RECOVERY хичээл өг → mastery_check → дараа нь өөрийн ангийн CORE хичээл
```

### Сэдвийг бүхэлд нь давтуулах цорын ганц тохиолдол

Нэг сэдвийн **is_primary чадваруудын тодорхой хувь (санал: 60%+) GAP** байвал —
тэр үед сэдвийг бүхэлд нь давтуулна. Үүнээс бусад тохиолдолд зөвхөн чадвар.

> Энэ босгыг тохиргоогоор өөрчилдөг болгоно. Бодит өгөгдөл дээр туршиж тааруулна.

## 7. Хуудасны шаардлага

### 7.1. Сурагч
- Өнөөдрийн хичээл (номын хэсэг + зорилго + тайлбар)
- Quiz бөглөх
- Миний ахиц: чадвар бүрээр MASTERED / DEVELOPING / GAP
- Оношилгооны түүх

### 7.2. Бага ангийн багш
- Ангийн жагсаалт
- **Оношилгооны оноо гараар оруулах дэлгэц** ← энэ дүрд онцгой
- Сурагч бүрийн түвшин
- Өдрийн агуулга сонгох
- Нэмэлт сорил өгөх

### 7.3. Дунд/ахлах ангийн багш
- Ангийн жагсаалт
- **Вэб оношилгооны үр дүн хянах** (гараар оруулахгүй)
- Задгай хариулт шалгах дараалал
- Сурагч бүрийн түвшин
- Өдрийн агуулга сонгох
- Нэмэлт сорил өгөх

### 7.4. Админ
- Ном оруулах, бүтэц (бүлэг/хуудас) тодорхойлох
- Сэдэв ↔ чадвар холбох
- Чадварын урьдач нөхцөл тохируулах
- 3 улирлын default хуваарь, анги бүрээр
- Хэрэглэгч, эрхийн удирдлага
- Материал баталгаажуулах (`DRAFT → IN_REVIEW → APPROVED`)

## 9. Эхний ээлжинд хийх ажил

### 9.1. Хийж чадах (2 өдөр)

1. **Багшийн шатлал** — `core.teachers`-д `stage` (`PRIMARY` / `SECONDARY`) нэмэх
   эсвэл `grade_from` / `grade_to`. Жижиг migration.
2. **Frontend нэвтрэх хуудас** — backend бэлэн, дутуу нь UI
3. **`native-learning.ts`-ийн `EJ_LOCAL_PREVIEW` хаалтыг арилгах**, `requireAuth` +
   `req.user.studentId`-аар солих
4. **Дүр тус бүрийн үндсэн хуудас, чиглүүлэлт** — 4 өөр shell
5. **Өдрийн хичээл харуулах** (1 PDF ном, mock хуваарь)
6. **Mock quiz** — сонголттой, түр өгөгдлөөр

### 9.2. Хэт өөдрөг байх магадлалтай ⚠

**Оношилгооны хөдөлгүүрийг 2 өдөрт багтаах нь бодитой биш.** Учир нь:
- Сонголттой асуултын хадгалалт **шинээр зохиох** ёстой (§8.2 #1)
- Хугацаа хянах, автомат илгээх
- Оноо → чадварын түвшин хөрвүүлэх дүрэм
- §6-ийн рекурсив нөхөх алгоритм

Энэ нь бие даасан блок — **3–5 өдөр**. 2 өдөрт багтаахыг оролдвол
хагас дутуу хэрэгжилт гарч, дараа нь дахин бичих магадлалтай.

**Санал:** 2 өдөрт §9.1-ийг бүрэн дуусга (нэвтрэлт + 4 дүрийн хуудас +
өдрийн хичээл + mock quiz). Оношилгоог дараагийн блок болго.

### 9.3. Хожим

- Бүх ном, бүх асуулт, материал оруулах (`staging` pipeline ашиглан)
- PDF-ээс автоматаар бүтэц гаргах
- Google Workspace холболт (одоогоор **хэрэггүй** — өмнөх шийдвэр)
- Тайлан, статистик

## 11. Тодруулах шаардлагатай

1. **Бага/дунд ангийн зааг** — 1–5 vs 6–11 мөн үү? Монголд 1–5 (бага),
   6–9 (дунд), 10–11 (ахлах) байдаг. "Дунд/ахлах" нэг дүр мөн үү?
2. **Оношилгооны давтамж** — "сар бүр" гэсэн. Тогтмол огноотой юу, багш
   эхлүүлдэг үү?
3. **Хугацааны хязгаар** — нийт шалгалтад уу, эсвэл асуулт тус бүрт?
4. **Одоогийн DB нь 9-р анги, Монгол хэл + Математик дээр л өгөгдөлтэй.**
   Эхний ээлжинд аль ангиар туршина?
5. **Сонголттой асуулт** — хэдэн сонголттой? Нэг зөв хариулт уу, олон уу?
6. **Оноо → түвшин хөрвүүлэх дүрэм** — хэдэн хувиас дээш бол `MASTERED`?
   (`mastery_checks.pass_rule_mn` талбар бий ч дүрэм тодорхойгүй)
7. **Сурагч нэвтрэх** — сурагч бүрт нэр/нууц үг үү, эсвэл багш кодоор оруулах уу?
8. **PDF харуулах** — бүтэн номыг үзүүлэх үү, зөвхөн тухайн өдрийн хуудсыг уу?
9. **Нэмэлт сорил** — багш өөрөө асуулт бичих үү, эсвэл сангаас сонгох уу?
10. **`content.skills` бүгд `DRAFT`** — сурагчид харагдахын тулд баталгаажуулах
    урсгал эхлээд хэрэгтэй. Хэн баталгаажуулах вэ — багш уу, админ уу?
