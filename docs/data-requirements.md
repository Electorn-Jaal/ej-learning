# Сургалтын туршилтад бэлтгэх өгөгдөл

Шинэчилсэн: 2026-09-21. Төлөв: өгөгдөл цуглуулах ажлын загвар; батлагдсан импортын формат биш.

## 1. Хамрах хүрээ

Энэ баримт нь багш–сурагчийн эхний сургалтын урсгалд хэрэгтэй өгөгдлийг тодорхойлно. Сургуулийн бүх системийн өгөгдлийн шаардлага биш. Аль анги, хичээл, хэдэн хүн оролцохыг эхлээд тохирно. Гурван хичээл, 30 сурагч гэх өмнөх тоонуудыг заавал биелүүлэх шаардлага гэж үзэхгүй.

Одоогийн database-ийн агуулга, тоог энэ засвараар шалгаагүй. Код болон seed script байгаа нь бодит агуулга бүрэн, зөв гэсэн баталгаа биш. Эхний хөгжүүлэлтийн туршилтад зохиомол сурагч ашиглана; бодит мэдээллийн хүрээ, хандах хүнийг сургуультай тохирно.

## 2. Өгөгдлийн холбоо

- Хичээлийн жил → анги → тухайн жилийн сурагчийн элсэлт.
- Багш → анги × хичээлийн хариуцлага.
- Ном ба хувилбар → бүлэг/хэсэг ба хуудас.
- Сэдэв ↔ чадвар (олон-олон, §2.1); сэдэв ↔ номын хэсэг.
- Өдрийн хичээл → зорилтот чадвар, материал; хуваарь/оноолт → анги эсвэл сурагч, хичээл, огноо.
- Асуулт → хэмжих чадвар, сонголт, баталгаажсан зөв хариулт.
- Үнэлгээ → сурагч, хэмжилтийн эх сурвалж, огноо, онооны дүрэм.

Номын нэг хэсгийг заавал нэг чадвар гэж үзэхгүй. Чадвар нь хэмжиж болох суралцахуйн үр дүн байна.

## 2.1. Сэдэв ба чадвар — юугаараа ялгаатай вэ

Энэ хоёрыг андуурах нь импортын хамгийн түгээмэл алдаа тул тусад нь бичив.

**Сэдэв** нь *юуг хэзээ заахыг* хэлнэ. Номын агуулгын хуудаснаас шууд гарна: «Бүлэг 3 — Бутархай тоо», доор нь «3.2 Бутархай тоо нэмэх».

**Чадвар** нь *сурагч юуг чаддаг болсныг хэмжих нэгж*: «Ижил хуваарьтай бутархайг нэмнэ».

Өөрөөр хэлбэл сэдэв бол **хуваарийн**, чадвар бол **үнэлгээний** ойлголт. Систем «сурагч 3.2-р сэдвийг үзсэн» гэж хэлдэггүй — «энэ чадварыг эзэмшсэн / сайжирч байна / дэмжлэг хэрэгтэй» гэж хэлдэг. Ахиц, дүн шинжилгээ, нөхөх сургалт гурав бүгд чадвар дээр тогтдог тул чадваргүй импорт нь зөвхөн номын жагсаалт болж үлдэнэ.

### Хамаарал нь олон-олон

Нэг сэдэв хэд хэдэн чадвар шаардаж болно, нэг чадвар хэд хэдэн сэдэвт давтагдаж болно.

| Сэдэв | Шаардах чадвар |
|---|---|
| 3.2 Бутархай тоо нэмэх | Хуваарь тэнцүүлэх · Бутархай хураах · Натурал тоо нэмэх |
| 3.3 Бутархай тоо хасах | Хуваарь тэнцүүлэх · Бутархай хураах · Натурал тоо хасах |

«Хуваарь тэнцүүлэх» хоёуланд нь орсныг анзаараарай. Энэ нь давхардал биш, харин системийн гол ашиг: сурагч 3.3 дээр бүдэрвэл яг аль чадвар нь дутуугаа, тэр чадварыг өмнө нь аль сэдэвт заасныг олж чаддаг.

Өгөгдлийн сангийн бүтэц үүнийг бүрэн зөвшөөрдөг. Одоогийн бодит агуулгад гэхдээ **42 сэдэв : 42 чадвар, яг нэг нэгээрээ** холбоотой байна — өөрөөр хэлбэл боломж нь бий, ашиглагдаагүй байна.

### Холбоосыг хэрхэн оруулах вэ

Энэ холбоос **тусдаа хүснэгтэд** хадгалагддаг (`content.content_skill_maps`); номын бүтцээс автоматаар гардаггүй. Тиймээс импортод **гурван тусдаа файл** хэрэгтэй:

1. Сэдвийн жагсаалт — номноос.
2. Чадварын жагсаалт — стандарт эсвэл багш нараас.
3. Аль сэдэв аль чадвартай холбогдохыг заасан **холбоосын жагсаалт**.

Гурав дахь файл нь хамгийн бага анзаарагддаг бөгөөд хамгийн чухал нь. Эхний хоёр нь байгаад гурав дахь нь дутуу бол систем хичээл товлож чадах ч ахиц хэмжиж чадахгүй.

### Гол чадвар

Холбоос бүр дээр «энэ нь тухайн сэдвийн **гол** чадвар мөн үү» гэсэн тэмдэг байна (`is_primary`). Өдрийн хичээлийн зорилго, сорилын гол хэмжилт үүгээр тодорхойлогдоно. Сэдэв бүрт гол чадвар яг нэг байх нь зүйтэй — **гэхдээ өгөгдлийн сан үүнийг одоо шалгадаггүй** тул бэлтгэлийн шатанд нүдээр шалгана.

### Хэн эзэмших вэ

Импортын дараа холбоосыг **«Агуулгын холбоо»** дэлгэцийн «Сэдэв ↔ чадвар» табаас шалгана (админ; **FR-F7**). Тэр хуудас чадваргүй сэдэв, гол чадваргүй сэдэв, батлагдаагүй холбоос, сэдэвт огт холбогдоогүй чадварыг жагсаана — импортын зөрүүг олох хамгийн хурдан газар.

Харин чадвар нэмэх, засах, холбоос үүсгэх дэлгэц **байхгүй**; зөвхөн script-ээр орно (**FR-F8**, **FR-F9**). Хэн эзэмших нь батлагдаагүй асуулт: [client-questions.md](client-questions.md) §5.

## 2.2. Сургуульд өгөх загвар файл

Бэлтгэх өгөгдлийг тайлбарлаад орхивол хүн бүр өөрийнхөөрөө багана зохионо.
Тиймээс бөглөх файлыг нь өөрсдөө үүсгэж өгнө:

~~~powershell
python scripts/src/make-import-template.py
~~~

`local-data/generated/ej-import-template.xlsx` — 9 хуудас, багана нэрлэгдсэн,
хуудас бүрд саарал өнгөөр жишээ мөр, эхний хуудсанд заавар. Жишээ мөрийг
бөглөж дуусаад устгана.

Энэ файл нь импортын **гэрээ** мөн: энд багана өөрчлөгдвөл уншдаг script
хамт өөрчлөгдөнө.

## 3. Цуглуулах талбарууд

Доорх нэрс нь бэлтгэлийн баганын санал. Одоогийн importer бүр өөр форматтай байж болох тул шууд оруулах амлалт биш.

| Бүрдэл | Шаардлагатай мэдээлэл | Тайлбар |
|---|---|---|
| Анги | class_code, нэр, ангийн түвшин, school_year | Код тогтвортой; хичээлийн жилтэй нь холбоно |
| Сурагч | student_code, харагдах нэр, class_code, school_year | Нууц үг, регистрийн дугаар энэ жагсаалтад шаардахгүй |
| Багш | teacher_code, нэр, анги, хичээл | Мөр бүр нэг багш–анги–хичээлийн хослол; бүртгэлийн username-ийг тусад нь тохирно |
| Ном | source_code, хичээл, гарчиг, хувилбар, PDF, нийт хуудас | Ашиглах зөвшөөрөл/эх сурвалж, PDF-ийн хувилбарыг тэмдэглэнэ |
| Номын бүтэц | outline_code, parent, гарчиг, дараалал, page_from, page_to | Хэвлэгдсэн хуудасны дугаар; ямар номын хувилбар болох нь тодорхой |
| Сэдэв | content_code, нэр, parent, түвшин, дараалал | Номын бүтэцтэй автоматаар адилтгахгүй. Түвшин: DOMAIN / UNIT / TOPIC / SUBTOPIC / SEGMENT |
| Чадвар | skill_code, нэр, хичээл, суралцахуйн үр дүн, анги эсвэл түвшин | Сэдвээс **тусдаа файл**. Хэмжиж болохуйц үйлдлээр бичнэ |
| Сэдэв–чадварын холбоос | map_code, content_code, skill_code, is_primary, тайлбар | **Заавал тусдаа файл** — номын бүтцээс гарахгүй (§2.1) |
| Хичээл | lesson_code, skill_code, төрөл, зорилго, тайлбар, жишээ, дасгал, материалын холбоос | CORE / RECOVERY / REINFORCE нь одоогийн загварын төрлүүд |
| Хуваарь | анги/сурагчийн код, хичээл, lesson_code, огноо, улирал | Оноолт нь гүйцэтгэл эсвэл үнэлгээ биш |
| Асуулт | item_code, skill_code, бичвэр, дараалал, оноо, сонголтууд, зөв хариулт, тайлбар | Одоогийн сорилын урсгалд нийцэх MCQ форматыг хөгжүүлэгчтэй тулгана |
| Урьдач нөхцөл | skill_code, prerequisite_skill_code, relation_type, шалтгаан | Багш баталгаажуулна; тойрог холбоосыг шалгана |
| Импортлох үнэлгээ | student_code, сорил/чадварын код, огноо, авсан/нийт оноо, эх сурвалж | Нийт онооноос чадвар тус бүрийн түвшинг нотолгоогүй гаргахгүй |

Нэг багш нэг ангид олон хичээл заах мэдээллийг алдагдуулахгүй цуглуулна. Өгөгдлийн сан үүнийг одоо шууд илэрхийлнэ — мөр бүр нэг багш–анги–хичээлийн хослол.

## 4. Чанарын дүрэм

### Анги ба хүний код

Кодуудыг Excel-д текстээр хадгална. 8-1 гэх утга огноо болж өөрчлөгдөж болно. Латин/кирилл үсэг болон 10-1, 10-A, 10А нь адил анги эсэхийг сургуулийн баталгаажуулсан зураглалаар шийднэ. Нүдээр төстэй гэдгээр нь автоматаар нэгтгэхгүй. Латин B нь Б эсвэл В эсэхийг таахгүй.

Нэрээр нь сурагч нэгтгэхгүй. Код байхгүй бол сургуультай тулгаж тогтвортой код олгоно. Анги солигдоход сурагчийн код өөрчлөгдөхгүй; элсэлтийн түүх тусдаа байна.

### PDF хуудас

Одоогийн код filePage = printedPage + pageOffset гэж тооцдог. Жишээлбэл хэвлэгдсэн 25-р хуудас PDF-ийн 37 дахь хуудас бол offset = 12. PDF-ийн индекс энд 1-ээс эхэлнэ. Хэд хэдэн хэсэгт шалгаж зөрүү тогтмол эсэхийг тогтооно; хуудас тасарсан/давтагдсан файлд ганц offset хангалтгүй.

Номын нэр, хувилбар, хуудасны мужийг багш баталгаажуулна. Өөр хичээлийн ном эсвэл зохиомол хуудасны холбоосыг бодит агуулга болгон хүлээн авахгүй.

### Сэдэв–чадварын холбоос

- Нэг хосыг (сэдэв, чадвар) хоёр удаа бичихгүй — өгөгдлийн сан давхардсан мөрийг татгалзана.
- Сэдэв бүрт гол чадвар (`is_primary`) яг нэг байхаар бичнэ. Database шалгахгүй тул файл дээр шалгана.
- Нэг ч сэдэвт холбогдоогүй чадвар ажиллана, гэхдээ түүнд номын хуудас олдохгүй. Ийм чадварын жагсаалтыг гаргаж багшаар шалгуулна.
- Холбоосыг устгахын өмнө түүнд тулгуурласан хичээл, асуулт байгаа эсэхийг шалгана — өгөгдлийн сан устгалыг хориглодог.

### Асуулт, үнэлгээ, нөхөх ажил

- Зөв хариулт, тайлбарыг багш эсвэл баталгаатай эх сурвалжаас авна. Сурагчдын нийт онооноос таамгаар сэргээсэн түлхүүрийг баталгаажуулалтгүй ашиглахгүй.
- Хэдэн асуулт хангалттайг хэмжих чадвартай нь уялдуулж шийднэ; 3–5 нь жишиг санал болохоос батлагдсан хэмжилтийн стандарт биш.
- Нөхөх сургалтад шаардлагатай урьдач чадвар бүр агуулга, асуулттай байна. Доод ангийн материал дутуу бол бэлэн гэж тэмдэглэхгүй.
- Одоогийн алгоритм APPROVED, REQUIRED холбоосыг дагадаг. Урьдач нөхцөл нь номын дарааллаас өөр ойлголт.
- Mock, багшийн хянасан, батлагдсан агуулгыг ялгана. AI-аар боловсруулсан агуулгыг багш хянана.

## 5. Хэн бэлтгэж, хэн хүлээн авах вэ?

| Хариуцагч | Ажил |
|---|---|
| Сургуулийн эрх бүхий хүн | Туршилтын хүрээ, сурагч/багш/анги, мэдээлэлд хандах эрхийг батлах |
| Хичээлийн багш | Материал, чадвар, асуулт, зөв хариулт, урьдач нөхцөл, хуваарийг хянах |
| Хөгжүүлэгч | Формат, давхардал, холбоос, импортын туршилт, алдааны тайлан |
| Менежер | Дутуу мэдээллийн эзнийг тодруулах, хүлээн авах ажлыг зохицуулах |
| Чадварын жагсаалтын эзэн (батлагдаагүй) | Чадвар аль стандартаас гарахыг шийдэх, сэдэв–чадварын холбоосыг батлах, шинэчлэх давтамжийг тогтоох (§2.1) |

## 6. Файл хүлээн авах дараалал

1. Туршилтын хүрээ болон зөвшөөрсөн мэдээллийн жагсаалтыг тохирно.
2. Эх файлыг өөрчлөхгүй хадгалж, зөвшөөрсөн хүрээний ажлын хуулбар гаргана. Бүх workbook-ийг шаардлагагүй хувийн мэдээлэлтэй нь нийтэд эсвэл GitHub-д оруулахгүй.
3. Хуудас бүрийн эх сурвалж, томьёо, кодын формат, дутуу талбарыг бүртгэнэ. Зөвхөн нийлбэр хүснэгт нь сурагч бүрийн чадварын үнэлгээнд хангалтгүй.
4. Сэдэв, чадвар, тэдгээрийн холбоосыг **гурван тусдаа файлаар** авна (§2.1). Холбоосын файл дутуу бол импортыг эхлүүлэхгүй — дараа нь гараар нөхөх ажил хамгийн үнэтэй нь.
5. Анги/хүний код, номын хувилбар, зөв хариултыг багшаар баталгаажуулна.
6. Тусдаа туршилтын database-д бага багцаар импортолж, холбоос ба тоог шалгана. Давтан импортын дүрмийг эхлээд тогтооно.
7. Материал → ажил → хариулт → багшийн үр дүн гэсэн бүтэн урсгалаар хүлээн авна.

Файл бүрд тэмдэглэх зүйл: өгсөн хүн, огноо, зориулалт, хичээл/анги, хуудасны нэр, эх сурвалж/томьёо, код ба зөв хариулт байгаа эсэх, дутуу зүйл, хянасан хүн.

## 7. Хамгийн бага туршилтын багц

Эхлээд нэг сонгосон анги/бүлэг, нэг багш, хязгаарлагдмал материал, хэмжиж болох чадвар, тохирох асуултаар бүтэн урсгал шалгах саналтай. Тоог тохиролцоно. Нөхөх ажил турших бол зориуд сул/эзэмшсэн/үнэлэгдээгүй жишээ, урьдач чадварын баталгаажсан агуулга нэмнэ.

Сурагчийн бодит хариулт, credential, backup, эх workbook нь кодын repository-д хадгалах материал биш. Кодод зөвхөн хувийн мэдээлэлгүй загвар, зохиомол fixture оруулна.

## 8. Файлыг хаана байрлуулах

Хүлээн авсан файлыг ажлын компьютер дээрх checkout-ийн local-data/ хавтсанд тавина. Энэ хавтас .gitignore-д орсон бөгөөд Git-д хэзээ ч орохгүй.

| Зам | Юу байх вэ |
|---|---|
| local-data/source/ | Хүлээн авсан workbook, PDF өөрчлөхгүйгээр. Эх файлыг засахгүй |
| local-data/extracted/ | scripts/src-ийн extract script-ийн гаргасан JSON |
| local-data/generated/ | Script-ийн үүсгэсэн бүртгэл, нууц үгийн жагсаалт |

Импортын урсгал: эх файл → extract script → local-data/extracted/*.json → import script → database.

~~~powershell
python scripts/src/extract-cefr.py "local-data/source/<workbook>.xlsx" local-data/extracted/cefr-extract.json
~~~

local-data/ нь Git-ээр хамгаалагдахгүй тул зөвхөн энэ компьютер дээр байна. Хэрэгтэй бол зөвшөөрөлтэй, тусдаа хадгалалтад нөөцлөнө. Database-ийн dump нь backups/, ажиллаж байгаа API-ийн хүргэдэг файл нь storage/ хавтсанд тусад нь байрлана.
