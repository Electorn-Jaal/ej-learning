# Хөгжүүлэлтийн суурь зохион байгуулалт

Огноо: 2026-09-18. Төлөв: хэлэлцэх ажлын хувилбар; удирдлагаар батлагдаагүй.

## Зорилго ба хариуцлага

Эхний зорилго нь багш–сурагчийн ажлыг дэмжих системийг хөгжүүлэх. Ирээдүйн сургуулийн бусад хэрэгцээг үе шаттай нэмнэ. Хөгжүүлэгч ганцаараа ажиллаж байгаа тул байгууллагын эзэмшил, баримтжуулалт, автомат шалгалт, гаднын техникийн хяналтаар ажлын үргэлжлэх боломжийг бүрдүүлнэ.

- Хөгжүүлэгч: техникийн санал, хэрэгжүүлэлт, шалгалт, ашиглалтын заавар.
- Менежер: хэрэгцээ, эрэмбэ, хэрэглэгчийн хүлээн авалт.
- Захирал эсвэл эрх бүхий хүн: төсөв, үйлчилгээний эзэмшил, хариуцлагын зөвшөөрөл.
- Гаднын хянагч: суурь шийдэл, ашиглалтад орох бэлэн байдал, дараагийн тогтмол техникийн хяналт. Хүн, хугацаа, төсөв хараахан тогтоогдоогүй.

## Кодын эхний үзлэгээр батлагдсан зүйл

| Хэсэг | Байрлал / технологи | Үүрэг |
|---|---|---|
| Хэрэглэгчийн интерфэйс | artifacts/ej-learning; React, Vite, TypeScript | Багш, сурагчийн browser дээр харагдах хэсэг |
| API сервер | artifacts/api-server; Node.js, Express | Хүсэлт, нэвтрэлт, эрх, ажлын логик |
| Өгөгдлийн сангийн холболт | lib/db; PostgreSQL, Drizzle | Байнгын өгөгдөлтэй ажиллах |
| API тодорхойлолт ба клиент | lib/api-spec, lib/api-zod, lib/api-client-react | Интерфэйс ба серверийн өгөгдлийн гэрээ |
| Файл хадгалалт | storage; EJ_STORAGE_DIR тохиргоо | Агуулгын файлууд; hosting дээр хадгалалтын шийдэл тусдаа шаардлагатай |
| Хөгжүүлэлтийн хэрэгсэл | pnpm workspace; package.json-д Node >=24, pnpm 10.28.2 | Олон package-ийг нэг repository-д удирдах |

Git repository, нэг commit болон нэг remote тохиргоо байна. Эхний үзлэгийн үед ажлын мод цэвэр байсан. Remote-ийн эзэмшил, хүртээмж, push хийсэн эсэхийг шалгаагүй.

Нэвтрэх, гарах, нууц үг солих route болон session, role шалгах middleware байна. Энэ нь аюулгүй байдлын аудит эсвэл бүх route зөв хамгаалагдсаны баталгаа биш.

Root scripts-д typecheck, build, test, db:setup, db:check байна. .env, backups/, storage/ нь .gitignore-д орсон; Git-ийн өмнөх түүхэнд нууц эсвэл хувийн мэдээлэл орсон эсэхийг шалгаагүй.

README болон холбогдох баримтыг 2026-09-18-нд шинэчилсэн. Одоогийн зөрүү, эрсдэл, шалгалтын хязгаарыг [хэрэгжүүлэлтийн төлөв](implementation-status.md)-т нэгтгэсэн.

## Орчны ойлголт

Хэрэглэгчийн browser → React интерфэйс → Express API → PostgreSQL.
API мөн шаардлагатай агуулгын файл хадгалалттай ажиллана.

- Local: хөгжүүлэгчийн компьютер; код бичих, турших орчин.
- Staging: шинэ хувилбарыг хязгаарлагдмал эрхтэйгээр турших тусдаа орчин; тусдаа database, нууц тохиргоотой байна.
- Production: бодит хэрэглэгчийн ашиглах орчин; бодит өгөгдөл, нөөцлөлт, хандалтын хяналттай байна.
- Deploy: шалгасан кодын хувилбарыг тухайн орчинд ажиллуулах.
- Hosting: интерфэйс, API болон бусад шаардлагатай хэсгийг ажиллуулах үйлчилгээ. PostgreSQL ба файлын хадгалалт багтсан эсэхийг тусад нь нягтална.
- Домэйн: хэрэглэгчийн хандах нэр; өөрөө application эсвэл өгөгдөл хадгалахгүй.

Local-оос бусад орчин одоо байгаа эсэх батлагдаагүй. Repository нь кодын түүхийг хадгална; database болон upload файлын нөөцлөлтийг орлохгүй.

## Дараагийн ажлын дараалал

Энэ бол нэг ажлын жагсаалт. Эрэмбийг менежертэй тохирч өөрчилж болно. Өмнөх session-ийн сервер асаалттай, тодорхой commit эсвэл database-ийн тоо хэвээр гэж таахгүй.

1. Repository-д үлдэх файл, нууц мэдээллийн эрсдэл, Git түүхийг нягтлах. Local эх файл, backup-ийг алдахгүй хадгална. 2026-09-18-нд эх өгөгдлийг local-data/ руу гаргаж, tracking-ээс хасч, түүхийг цэвэрлэсэн; үлдсэн ажлыг [хэрэгжүүлэлтийн төлөв](implementation-status.md#github-руу-илгээхийн-өмнө)-д бичсэн.
2. Хэрэглэгдэж байгаа хөгжүүлэлтийн болон сурагчийн бүртгэлийн нууц үгийг солих. Хуучин утга дурдагдсан файл, лог, чатыг мөн шалгана.
3. Шинэ Organization repository-ийн хаягийг авч local remote-той тулгах. Хэрэглэгчийн мэдээлснээр Organization болон private repo үүссэн, менежер Owner урилгаа хүлээн авсан; GitHub дээр тусад нь шалгаагүй.
4. Local орчны хувилбар, тохиргооны нэр, build ба шалгалтын бодит үр дүнг баримтжуулах. Database-д хүрэх тестийн нөлөөг эхлээд уншиж шалгах.
5. Шинэ local database-ийг зөв baseline, зохиомол seed-ээр босгох давтагдах урсгал. Хийгдсэн: `db:setup` (chore/local-setup branch), тусдаа туршилтын database дээр эхнээс нь шалгасан. Үлдсэн нь бусад хөгжүүлэгчийн компьютер дээр давтан батлах.
6. Auth-тай integration test. Хийгдсэн: `corepack pnpm test` нь түр database дээр 15 шалгалт ажиллуулна, test:db-г орлуулсан. Branch / pull request урсгал тогтсон. GitHub Actions нь PR бүрт build ба test ажиллуулна (.github/workflows/ci.yml). Өөрийн review нь бие даасан хяналт биш.
7. Байгууллагын repository эзэмшил, account сэргээх хариуцлага, гишүүдийн эрхийн санал гаргах. Хувийн account-аар ажиллах ба байгууллагын эзэмшлийг ялгах.
8. Багшийн өгөгдлийн хүрээ, үнэлгээ дахин бодох эрсдэл, олон хичээлийн хариуцлагын хязгаарыг шийдэх.
9. Туршилтын анги, хичээл, материал, сургалтын дүрмийг багш/менежертэй баталгаажуулах.
10. Хэрэглэгчийн тоо, файл, төсөв, арчилгааны ачааллаар hosting-ийн хувилбаруудыг судлах. Одоогоор provider сонгоогүй.
11. Менежер, захиралд хүрээ, зардал, эзэмшил, хариуцлага, хэрэгжүүлэх үе шатыг танилцуулж шийдвэрлүүлэх.
12. Зөвшөөрсөн үйлчилгээ, staging орчин байгуулж, гаднын анхны техникийн хяналт хийлгэх.
13. Production-оос өмнө эрх, чухал урсгал, нөөцөөс сэргээх, deploy буцаах ажиллагааг шалгаж, хэрэглэгчийн хүлээн авалт хийх.

## Ажлын зарчим

- Хэрэглэгчийн шинэ чиглэлийг өмнөх mock үеийн баримтаас дээгүүр баримтална.
- Кодод байгаа боломжийг runtime-аар баталгаажсан гэж бичихгүй.
- API гэрээ → codegen → хэрэгжүүлэлт → шалгалт.
- Schema → migration SQL хяналт → тусдаа орчны туршилт → хэрэглэх.
- Database өөрчилдөг script-ийг эхлээд уншина. reset, rebuild, seed, restore нь энгийн startup биш.
- Нууц үг, token, сурагчийн эх мэдээлэл, backup-ийг Git-д оруулахгүй. Нууц утгыг тайлан, issue, чатад гаргахгүй.
- Байгаа backups/, storage/, local-data/ файлуудыг устгахгүй. Restore нь тусдаа database дээрх хянасан ажиллагаа байна.

Ажиллуулах заавар: [README](../README.md). Өгөгдөл бэлтгэх: [data-requirements.md](data-requirements.md).

## Удирдлагаас тодруулах мэдээлэл

- Домэйн, байгууллагын имэйлийн үйлчилгээ болон тэдгээрийн эзэмшигч, төлбөр хариуцагч.
- Үйлчилгээ болон гаднын хяналтад төлөвлөж болох төсөв.
- Туршилтад оролцох багш, сурагчдын ойролцоо тоо, хугацааны хүлээлт.
- Байгууллагын account сэргээх, хөгжүүлэгч байхгүй үед холбоо барих эрх бүхий хүн.
- Бодит мэдээлэлд хандах эрх ба хэрэглээний хүрээг шийдэх хүн.

Нууц үг, recovery code, API key-г энэ баримтад бичихгүй.

## Энэ үзлэгийн хязгаар

Энэ нь эх код ба тохиргооны хэсэгчилсэн, унших үзлэг. Систем ажиллуулж, database холбож, тест ажиллуулж, remote үйлчилгээ шалгаагүй. Deploy хийх бэлэн байдал, аюулгүй байдал, өгөгдлийн бүрэн бүтэн байдлын баталгаа биш. Код, account, database, remote тохиргоонд өөрчлөлт хийгээгүй.

## Account зохион байгуулалтын явц

Хэрэглэгчийн мэдээлснээр сургуулийн Organization болон private repository үүссэн, менежер Owner болсон. Одоохондоо Free-ээр эхлэхээр тохирсон. GitHub дээрх тохиргоо, repo URL, local remote холболтыг энэ засвараар баталгаажуулаагүй. Сарын техникийн хяналтын төсөв, хүн хараахан тогтоогдоогүй.
